# ماشه‌ی پروب، روی Cloudflare Workers

این پوشه یک Worker است که هر ۱۰ دقیقه workflow پروب را در گیت‌هاب اجرا
می‌کند. تا وقتی deploy نشده باشد هیچ کاری نمی‌کند و بقیه‌ی مخزن بدون آن هم
همان‌طور کار می‌کند که می‌کرد، فقط با همان زمان‌بند غیرقابل اتکا.

## چرا لازم شد

رویداد `schedule` در گیت‌هاب اکشنز کار نمی‌کند. اندازه‌گیری روی همین مخزن، نه
حدس:

| بازه | cron چه خواست | چه گرفتیم |
| --- | --- | --- |
| ۱۳ ساعت | حدود ۷۸ ران | **۷ ران** |

و هر رانی که اجرا شد، حداکثر پنج دقیقه با دقیقه‌ی درخواستی فاصله داشت. یعنی
مسئله تأخیر نیست: گیت‌هاب از هر شش درخواست، پنج‌تا را بی‌صدا دور می‌ریزد. نه
خطایی، نه رانی در صف. هیچ چیزی داخل این مخزن این را عوض نمی‌کند.

## چرا فقط ماشه و نه کل صفحه

`workers.dev` در ایران فیلتر است. اگر صفحه یا حتی فقط `history.json` از اینجا
سرو می‌شد، مرورگر مشتری ایرانی به آن نمی‌رسید، یعنی دقیقاً همان کسی که این
صفحه برایش ساخته شده. راه دیگرش این بود که کل zone یعنی `segmentic.net` از
ArvanCloud به کلادفلر منتقل شود، که یعنی عوض کردن مسیر رسیدن کاربر به خودِ
محصول، برای درست کردن صفحه‌ی وضعیت.

این Worker را هیچ‌کس باز نمی‌کند. فقط سرِ cron بیدار می‌شود و یک درخواست به
API گیت‌هاب می‌زند. پس فیلتر بودن `workers.dev` اینجا بی‌اثر است.

## توکن

یک fine-grained token لازم است، که این طراحی عمداً نداشت. اندازه‌ی خطرش:

* فقط روی مخزن `Segmentic1/status`، که **عمومی** است.
* فقط با دسترسی `Actions: Read and write`. نه `Contents`، نه چیز دیگر.
* اگر لو برود، تنها کاری که می‌شود کرد اجرای بیشترِ پروبِ خودمان است. رازی
  برای خواندن نیست و کدی برای عوض کردن نیست.

توکن به عنوان secret در خود Worker می‌نشیند، نه در این مخزن و نه در secrets
گیت‌هاب.

## راه‌اندازی

۱. در گیت‌هاب: `Settings > Developer settings > Personal access tokens >
   Fine-grained tokens`. فقط مخزن `Segmentic1/status`، دسترسی
   `Actions: Read and write`، انقضا حداکثر یک سال.

۲. بعد از این پوشه:

```bash
npx wrangler login          # مرورگر باز می‌کند، از ایران احتمالاً پروکسی می‌خواهد
npx wrangler deploy
npx wrangler secret put GITHUB_TOKEN   # توکن را همین‌جا paste کنید
```

۳. یک بار دستی امتحان کنید:

```bash
npx wrangler tail                       # در یک ترمینال باز بماند
gh run list --repo Segmentic1/status    # ران‌ها را ببینید
```

`schedule` در `probe.yml` عمداً حذف نشده و به عنوان پشتیبان سر جایش می‌ماند.
هر وقت اجرا شود، ضرری ندارد.

## بعد از اینکه کار کرد

`SAMPLES` در `probe.mjs` الان ۵ است. آن عدد جبرانِ همین زمان‌بند خراب بود:
وقتی ساعتی فقط یک ران می‌گرفت، آن ران باید بیش از یک لحظه را گزارش می‌کرد. با
ماشه‌ی قابل اتکا دیگر لازم نیست و می‌شود آورد روی ۲، که هم ران کوتاه‌تر شود و
هم مصرف رانرهای رایگان گیت‌هاب منصفانه‌تر بماند. اول یک روز اندازه بگیریم، بعد
دست بزنیم.
